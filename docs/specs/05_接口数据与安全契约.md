# 接口、数据与安全契约

## 1. 目的

本文件约束 rrenn.com、Rrenn Cloud API、RenWork Desktop/Local、TeamAI 和外部系统之间的接口。Codex 实现时先生成 OpenAPI/JSON Schema 与类型，再写调用代码；不得让两个仓库靠复制内部 TypeScript 类型保持“同步”。

## 2. 边界与命名

| 边界 | 协议 | 版本策略 |
|---|---|---|
| 官网 → 同源 API | HTTPS JSON | `/api/v1` |
| RenWork → Cloud API | HTTPS JSON/SSE | `/v1` + 客户端能力协商 |
| Cloud API → RenWork | Webhook/事件轮询 | event `schema_version` |
| RenWork → Local Adapter | 现有 IPC/runtime | 遵循仓库现有契约 |
| RenWork → MCP | MCP tools/resources | server/tool schema 版本 |
| TeamAI → RenWork | Git 内容 + manifest | commit SHA + schema version |
| 官网 → Release | 签名 JSON manifest | `manifest_version` |

名称规范：外部 JSON 使用 `snake_case` 或项目既有单一规范，不混用；ID 为不可猜 UUID/ULID；时间为 UTC ISO 8601；货币为整数最小单位 + ISO 4217。

## 3. 官网 API

### 3.1 Health

```http
GET /api/v1/health/live
GET /api/v1/health/ready
```

`live` 只判断进程；`ready` 检查必需依赖但不泄露连接串/版本细节。

### 3.2 Lead

```http
POST /api/v1/leads
Idempotency-Key: <uuid>
Content-Type: application/json
```

请求示例：

```json
{
  "company_name": "Example Manufacturing",
  "website": "https://example.com",
  "contact_name": "Li Ming",
  "job_title": "Export Manager",
  "work_email": "name@example.com",
  "phone": null,
  "whatsapp": null,
  "products": ["industrial equipment"],
  "target_markets": ["DE", "US"],
  "team_size_range": "6-20",
  "pain_points": ["buyer_discovery", "contact_discovery"],
  "preferred_contact_time": "weekday_afternoon_asia_shanghai",
  "privacy_policy_version": "2026-08-22",
  "privacy_consent": true,
  "marketing_consent": false,
  "attribution": {
    "utm_source": "linkedin",
    "utm_medium": "organic",
    "utm_campaign": "growth_os",
    "landing_path": "/product/buyer-intent",
    "referrer": "https://www.linkedin.com/"
  }
}
```

响应：

```json
{
  "lead_id": "01J...",
  "status": "accepted",
  "request_id": "01J...",
  "next": "/diagnosis/thanks"
}
```

约束：

- 客户端与服务端都用 Zod/JSON Schema 校验；服务端为事实源；
- `privacy_consent` 必须为 true；营销同意独立；
- 幂等键 + 规范化 email/company 去重，但不把不同业务询问静默合并；
- 返回稳定错误码：`VALIDATION_FAILED`、`RATE_LIMITED`、`BOT_SUSPECTED`、`CONSENT_REQUIRED`、`INTEGRATION_DEGRADED`；
- CRM/邮件通知失败时仍可接收主记录，进入异步重试。

### 3.3 Public content

V1 内容以构建时 MDX 为主。需要运行时接口时只暴露已发布、非敏感字段：

```http
GET /api/v1/public/releases/stable
GET /api/v1/public/releases/{version}
GET /api/v1/public/status
```

## 4. Release Manifest

```json
{
  "manifest_version": 1,
  "product": "renwork",
  "channel": "stable",
  "version": "0.18.43",
  "published_at": "2026-08-21T00:00:00Z",
  "git": {
    "repository": "cnproduct/renwork",
    "commit": "<40-char-sha>",
    "release_url": "https://github.com/cnproduct/renwork/releases/tag/v0.18.43"
  },
  "artifacts": [
    {
      "platform": "windows",
      "arch": "x64",
      "format": "exe",
      "size_bytes": 123456789,
      "sha256": "<64-hex>",
      "signature": "verified",
      "primary_url": "https://download.example.invalid/renwork.exe",
      "fallback_url": "https://github.com/..."
    }
  ],
  "minimum_supported_version": "0.17.0",
  "notes_url": "https://www.rrenn.com/insights/releases/0-18-43",
  "signature": "<detached-signature>"
}
```

生产 URL 使用真实受控域名。manifest 在 CI 生成、签名，服务端只发布验证通过的 artifact；官网显示 SHA-256。镜像任务校验 GitHub artifact hash 后才标记 available。

## 5. 品牌 Manifest

V1 两仓库可分别存资产，但必须附相同 manifest：

```json
{
  "brand_schema_version": 1,
  "brand_release": "2026.08",
  "assets": {
    "rrenn_logo_horizontal": {
      "path": "/brand/rrenn-logo-horizontal.svg",
      "sha256": "<hash>",
      "approved": true
    },
    "renwork_product_mark": {
      "path": null,
      "sha256": null,
      "approved": false
    }
  },
  "tokens": {
    "brand_ink": "#211513",
    "brand_orange": "#E06A14",
    "brand_orange_action": "#C55208"
  }
}
```

未经批准的资产不能因为 manifest 字段为空就由 Codex“补画”。后期可发布 `@rrenn/brand`，但运行时不得依赖 GitHub raw 文件。

### 6.5 EvidenceRef

每个关键结论引用证据：

```ts
type EvidenceRef = {
  id: string;
  sourceType: "customs" | "website" | "okki" | "linkedin" | "news" | "user" | "provider";
  sourceId: string | null;
  sourceUrl: string | null;
  observedAt: string;
  capturedAt: string;
  excerpt: string | null;
  confidence: number;
  access: "public" | "workspace" | "restricted";
};
```

`excerpt` 有版权和敏感限制，默认只保留必要摘要。

## 7. 任务与审批模型

```ts
type TaskStatus =
  | "draft"
  | "queued"
  | "running"
  | "awaiting_approval"
  | "paused"
  | "succeeded"
  | "failed"
  | "cancelled";

type Approval = {
  id: string;
  taskId: string;
  action: "send_email" | "linkedin_interaction" | "crm_write" | "export_pii" | "spend_credits";
  requestedBy: string;
  requestedAt: string;
  decision: "pending" | "approved" | "rejected" | "expired";
  decidedBy: string | null;
  policyRefs: string[];
};
```

审批 token 有短时有效期，绑定 task/action/payload hash；payload 变化后必须重新审批。

## 8. MCP 工具契约

每个工具 schema 至少包含：

- `workspace_id`、`request_id`、`idempotency_key`；
- 明确查询范围/字段；
- `dry_run`（有副作用时）；
- `approval_id`（高风险写操作时）；
- 分页游标而非不受限结果；
- 标准错误：auth、permission、rate limit、validation、provider unavailable、human required；
- 输出 `source_refs`、`provider_request_id`、`credits_reserved/settled`。

工具命名示例：

```text
customs.search_shipments
customs.resolve_company
contact.import_candidates
contact.verify_email
crm.upsert_lead
email.create_draft
email.send_approved
social.create_draft
social.publish_approved
```

`linkedin.auto_like`、`linkedin.auto_comment` 等暗示无人审批或规避限制的工具名不得进入默认能力集。

## 9. TeamAI Manifest

```yaml
schema_version: 1
team_id: example-team
revision: <git-commit-sha>
skills:
  - id: buyer-intent
    path: .teamai/skills/buyer-intent/SKILL.md
    version: 1.2.0
    risk: read_only
hooks:
  - id: outreach-compliance
    phase: pre_tool
    applies_to:
      - email.send_approved
    blocking: true
mcp_profiles:
  - id: production-default
    path: .teamai/mcp/mcp.yaml
    secrets: external
wiki_roots:
  - teamwiki/products
  - teamwiki/markets
```

密钥只引用环境变量/Keychain 中的 secret name，manifest 不包含值。同步前验证 schema、路径、防目录穿越、允许的 Hook/MCP 和提交来源。

## 10. 事件契约

```json
{
  "event_id": "01J...",
  "event_type": "outreach.email.sent",
  "schema_version": 1,
  "occurred_at": "2026-08-22T12:00:00Z",
  "tenant_id": "01J...",
  "workspace_id": "01J...",
  "actor": { "type": "user", "id": "01J..." },
  "subject": { "type": "contact", "id": "01J..." },
  "correlation_id": "01J...",
  "payload": {
    "message_id": "01J...",
    "provider": "zoho",
    "approval_id": "01J..."
  }
}
```

事件 payload 不放正文/完整联系人；需要时通过权限受控 API 获取。消费者必须幂等，未知字段向前兼容。

## 11. 身份、租户与授权

- 官网公开 API 不与 RenWork 管理 API 共用匿名权限；
- RenWork Cloud 使用短时 access token + 可撤销 refresh/device session；
- tenant/workspace/role 在服务端校验，不能信任前端传入 owner；
- 最小角色：Owner、Admin、Manager、Operator、Reviewer、Viewer；
- 导出 PII、管理连接器、购买 Credits、修改团队 Hook 分开授权；
- 服务间使用独立身份和 scope；
- 管理员 impersonation 如存在必须提示、限时和审计。

## 12. PII 与保留

数据分类：Public、Internal、Confidential、Restricted。联系人、邮件、电话、交易证据通常至少 Confidential；凭证和会话为 Restricted。

要求：

- 传输 TLS；数据库/备份加密；
- UI 默认遮罩 Restricted/敏感字段；
- 日志仅存 hash/ID；
- 导出水印/审计/过期；
- Workspace 可配置保留期；
- 删除流程覆盖主库、索引、缓存和后续备份过期；
- 抑制名单保留最少必要不可逆 hash，避免删除后再次发送；
- 第三方数据源的许可和删除义务进入 provider registry。

## 13. 外发合规与平台安全

- 营销邮件支持发件主体、联系理由、地址（适用时）、退订和抑制；
- 频率、时区、域健康和退信策略由组织 Hook 强制；
- LinkedIn 等平台的自动化边界可能变化，发布功能前核对当前官方条款；
- 不提供绕过 CAPTCHA、封禁、限流或机器人检测的功能；
- 合规规则不是法律意见，企业应由律师/合规负责人确认适用地区要求；
- 数据供应商须有合同、用途和留存记录。

## 14. 错误与可观测性

统一错误：

```json
{
  "error": {
    "code": "APPROVAL_REQUIRED",
    "message": "This action requires user approval.",
    "request_id": "01J...",
    "retryable": false,
    "details": { "action": "send_email" }
  }
}
```

面向用户的 message 可本地化；code 稳定。不要向客户端返回 stack、SQL、token、provider secret。trace 使用 correlation id 贯穿 Web/API/worker/MCP，但 PII 不进入 trace tag。

## 15. 契约测试与变更

- OpenAPI/JSON Schema 进入仓库，CI 校验 breaking changes；
- 生成客户端类型但提交生成规则/版本；
- consumer/provider contract test 覆盖官网与 RenWork；
- 新字段可选、旧客户端可忽略；删除/重命名走 deprecation；
- manifest/事件按 schema version 迁移；
- API 变更必须更新本文件、用户文档和 changelog；
- 测试 fixture 必须合成或脱敏。
